Engineering Assessment · Artwall 3.0

From working prototype to a platform galleries can trust

Artwall 3.0 mints blockchain-backed certificates of authenticity end to end today. This is a candid read of the thirteen layers between that and something a gallery, an auditor, or an acquirer would sign off on — and the order to fix them in.

Assessed 2026-09-06 · commit d6e2ff9 Stack Next.js 14 · Prisma/Supabase · wagmi + RainbowKit · OZ ERC-721/2981 on Base Live localhost + Base Sepolia testnet
00

The verdict

The product is real and the architecture is sound. What makes it a prototype is not missing features — it is that almost nothing is verified, reproducible, or observed.

The certificate wizard, IPFS pinning, database, auth, and an on-chain mint all work. But the database schema was applied by hand and isn't in the repo; the app talks to Postgres as a superuser so row-level security does nothing; the mint is declared complete by the browser with no on-chain confirmation; the contract lets anyone mint anything into your collection; there is no error tracking, no CI, no tests beyond one contract case, and no Terms of Service for a document that carries legal weight. None of these are hard to fix. They just all have to be fixed before real works and real money flow through it.

Two changes gate everything else: make the mint path server-authoritative (§01) and get migrations into CI against a dedicated database (§03). Growth work built before those compounds on sand.

01

The one flaw that matters most: mint integrity

Everything downstream — the dashboard, the public verification page, a gallery's trust — assumes the database knows the truth about what is on-chain. Right now it doesn't. The browser tells it, and the browser is never checked.

Now — the client is the source of truth

Browser User clicks Mint; wallet signs mintCertificate()
Chain Transaction may succeed, fail, or drop
Browser On success it POSTs { txHash, tokenId } to the API
API Checks auth + ownership, then writes status = MINTED — no on-chain check

Target — the indexer is the source of truth

Browser User redeems a platform-signed mint voucher; record moves to MINTING only
Chain Contract emits CertificateMinted(tokenId, to, uri)
Indexer Ingests the event via RPC webhook; confirms contract, sender, real tokenId
API Sets MINTED / FAILED from the event; a watchdog reconciles stragglers
01

What breaks today

Forgeable state
Any signed-in owner can PATCH a draft to MINTED with a fabricated transaction hash. The verification page will present it as authentic.
Stuck records
A genuine mint whose follow-up API call fails (tab closed, network blip) is frozen at METADATA_PINNED forever — there is no retry and no reconciliation.
Blind to reality
Secondary sales, transfers, and burns never reach the database. Provenance — the entire point — goes stale the moment the token moves.
01

The move

P0
Server-authoritative lifecycle
The client may only ever set MINTING. A minimal indexer (Alchemy or QuickNode address-activity webhooks to start) confirms CertificateMinted and Transfer events and is the only writer of MINTED, FAILED, and every ownership change.
Mint authorization
Issue an EIP-712 signed voucher from the backend that the user redeems on-chain (they still pay gas), or run a relayer / paymaster for a gasless flow. Either way the platform — not an open contract method — decides what may be minted.
Live verification
The public /verify page reads the current on-chain owner and re-checks that tokenURI still resolves to the metadata hash on record.
02

Frontend & wizard UX

02

Certificate wizard, dashboard, verification pages

Harden
Now
Wizard state is component useState — a refresh loses every field and the uploaded image. The Zod schemas exist but aren't wired to the inputs, so there is no inline validation. The component set is five primitives; there are no loading skeletons, empty states, error boundaries, or toasts, and images render through a raw unbounded <img>.
Breaks when
A cataloguer enters a 20-field record for a valuable piece and loses it; a gallery does a bulk session and hits an unhandled error with no recovery; a large upload janks the layout on a mid-range laptop.
The move
Persist the draft server-side on every step with debounced autosave; enforce Zod per field with aria-live error text; adopt the full design-system component set on Radix primitives with tokens and a working theme toggle; wrap every route segment in an error boundary; drive all mutations through React Query with optimistic UI and rollback; serve images via next/image and an image CDN; gate merges on Lighthouse and axe so the wizard and mint flow stay keyboard- and screen-reader-complete.
03

Database & migrations

03

Postgres, Prisma, the artwall schema

Rework
Now
Artwall shares a Supabase project with an unrelated live app, isolated only by a Postgres schema. There is no prisma/migrations/ folder — the schema was diffed and applied through an MCP tool, so it can't be reproduced or reviewed. The app connects as the postgres role, which means the row-level security that is switched on does nothing. No point-in-time-recovery test, no seed script, no DB-level check constraints.
Breaks when
A second engineer can't stand up the schema; a bad deploy has no reviewed migration to roll back; a single leaked connection string reaches every table with no RLS backstop; basisPoints above 10000 or an impossible status transition slips through because only application code guards it.
The move
Move to a dedicated database (own Supabase project, or Neon/RDS). Commit real Prisma migration files and run migrate diff in CI against a shadow database on every PR. Create a least-privilege application role and turn RLS on as defense in depth even though the API also authorizes. Pool connections (Supabase pooler or Prisma Accelerate) for serverless. Add check constraints (basisPoints 0–10000, valid chainId, enum-guarded status). Enable PITR, take nightly logical backups to object storage, and rehearse a restore. Add a read replica once verification traffic grows.
04

API layer

04

Route handlers: upload, certificates, mint callback

Harden
Now
/api/ipfs/upload is unauthenticated and unmetered — anyone can exhaust the Pinata quota. Raw error .message strings are returned to clients. No rate limiting, request logging, idempotency keys, or body-size / MIME allow-list. The mint callback trusts client-supplied fields.
Breaks when
A scraper burns the storage budget overnight; an internal stack detail leaks in an error; a double-submit creates duplicate certificates; a 200 MB upload lands on a serverless function.
The move
Require auth on every mutating route including upload; add per-user and per-IP rate limits (Upstash Redis or the platform WAF); attach a correlation id and emit structured logs per request; require idempotency keys on create and mint; enforce a strict size cap and MIME allow-list; map errors to stable codes and never echo internals; add contract tests and publish an OpenAPI spec once galleries integrate.
05

Auth & identity

05

Supabase Auth, sessions, the missing org model

Harden
Now
Email + password and magic link. Email confirmation was turned off during setup; leaked-password protection is off (Supabase's own advisor flags it). No MFA, no auth rate limiting, no session list, no wallet-based sign-in even though a walletAddress column exists. No concept of an organization, so a gallery is just one shared login.
Breaks when
A creator handling six-figure works has only a password; a gallery needs five cataloguers with different permissions and an audit trail; an enterprise customer requires SSO.
The move
Re-enable email confirmation and leaked-password protection; add TOTP MFA; add Sign-In-With-Ethereum so a wallet is a cryptographically-bound login. Introduce an Organizations model (org, membership, roles: owner / admin / cataloguer / viewer) and SAML/OIDC SSO for enterprise galleries. Add a security-event audit log and a device/session list with revoke.
06

Smart contracts & key management

06

ArtwallCOA — ERC-721 + ERC-2981

Rework
Now
mintCertificate() has no access control — any address can mint any metadata URI into the collection. owner is a single externally-owned key (the deploy key that briefly sat in .env). No audit, no pause, no upgrade path, no ERC-4906 metadata-update events, no batch mint. One royalty receiver, though the spec calls for automated splits. Deployed to Base Sepolia only.
Breaks when
A competitor mints garbage into your collection and it shows on marketplaces; the single owner key is lost or phished; a gallery wants a 60/40 split between artist and estate; you need to correct metadata after a typo and can't.
The move
Gate minting behind a MINTER_ROLE backend signer or an EIP-712 voucher redemption. Move owner and admin roles to a Gnosis Safe multisig. Commission a professional audit (OZ, Spearbit, Trail of Bits) and run Slither + Foundry invariant tests in CI. Add Pausable, ERC-4906, and enumeration (on-chain or indexed). Decide upgradeability deliberately — UUPS proxy, or "immutable, new collection per version". For splits, deploy a 0xSplits or PaymentSplitter per work and set it as the ERC-2981 receiver. Deploy to Base and Polygon mainnet behind a per-chain address registry, with a written key-rotation and incident runbook.
07

Storage & IPFS permanence

07

Pinata, the gateway, image handling

Rework
Now
A single Pinata account on the free tier (1 GB), one gateway, no redundancy. "Pinned" is not "permanent" — if the account lapses, the art is gone. Uploads are stored as-is: no re-encoding, EXIF stripping, virus scan, dimension or size cap, perceptual-hash dedupe, or moderation. Nothing checks that the on-chain tokenURI still matches what the database believes.
Breaks when
Billing lapses and every certificate's image 404s; a malicious file is served from your gateway; the same stolen image is certified twice; a metadata file is quietly altered after minting.
The move
Pin to Pinata and a second provider (web3.storage / Filebase), and mirror to Arweave (pay-once permanence) or Filecoin deals for the canonical copy. Process every upload: re-encode, strip metadata, generate responsive derivatives to an image CDN, ClamAV scan, and route to a moderation queue. Store the content hash and re-verify tokenURI against it on every verification view. Run a dedicated gateway on a custom domain with caching and cost alerts.
08

Payments & multi-tenancy

08

Billing, plans, seats, metering

Not built
Now
Nothing. The spec describes subscription tiers and B2B gallery accounts; there is no billing, plan enforcement, seat management, or usage metering.
Breaks when
The moment you want revenue, or to cap a free user's storage and chains.
The move
Stripe Billing with plans (free / creator / gallery / enterprise) and metered add-ons (extra IPFS storage, extra chains). Seats tied to the Organizations model; entitlement checks in middleware; dunning, invoices, and Stripe Tax. A usage pipeline recording certificates minted, storage consumed, and API calls.
09

Observability

09

Logs, errors, traces, metrics, uptime

Not built
Now
console.log and console.error. No error tracking, tracing, metrics, uptime checks, or product analytics. When a mint fails in production you will not know it happened.
Breaks when
Immediately — the first production incident is invisible until a user emails.
The move
Sentry across frontend, API, and edge with release health. Structured JSON logs shipped to a store (Axiom, Better Stack, Datadog). OpenTelemetry traces spanning API → DB → RPC → IPFS. RED metrics with dashboards and on-call alerts against explicit SLOs — verification p95, mint-confirmation lag, IPFS pin success rate. Synthetic checks on the sign-up → catalogue → mint path. PostHog for the wizard funnel.
10

Security

10

Secrets, headers, abuse, supply chain

Harden
Now
Secrets live in a local .env; a deploy private key was pasted into it as plaintext. No Content-Security-Policy or security headers. Error messages leak internals. No rate limiting, no dependency scanning, no secret scanning, an unauthenticated upload route, and no CSRF/origin guard on cookie-authenticated POST routes.
Breaks when
The deploy key is exposed and drains the wallet; a dependency CVE ships to production unnoticed; a cross-site POST creates certificates as a logged-in user.
The move
Move secrets to a manager (encrypted platform env + Doppler / 1Password) and rotate the deploy key now; signing should go through a dedicated deployer or a KMS/hardware signer, never a raw key in the tree. Add a strict CSP, HSTS, X-Content-Type-Options, Referrer-Policy, Permissions-Policy. Enforce SameSite plus origin checks or CSRF tokens on mutating routes. Gate CI on npm audit / Snyk and run gitleaks pre-commit and in CI. Publish a SECURITY.md, run a pen test before public launch, and open a bug bounty after.
11

Compliance & legal

11

Terms, privacy, an immutable ledger vs. the right to erasure

Not built
Now
No Terms of Service, Privacy Policy, or stated legal basis for processing — for a document that makes an authenticity claim with commercial weight.
Breaks when
An EU artist files a data-subject request; a disputed-authorship takedown arrives; a high-value sale triggers KYC/AML expectations; a tax authority asks how royalty income is reported.
The move
Terms of Service and Privacy Policy, plus a plain statement of what the certificate legally asserts and does not. A GDPR/CCPA program with a data-subject-request workflow — and a deliberate design for erasure against an immutable chain: keep all PII off-chain in deletable storage and commit only hashes on-chain. A records-retention schedule. OFAC/sanctions screening on wallet addresses and KYC thresholds for high-value works. Artist IP warranty and a DMCA-style takedown process. A WCAG 2.2 AA conformance statement.
12

Infrastructure & CI/CD

12

Pipeline, environments, migrations, DR

Rework
Now
Everything is manual. No CI, no automated tests in a pipeline, no preview environments, migrations applied by hand, no rollback plan, single region.
Breaks when
A broken build reaches production because nothing checked it; a migration corrupts data with no tested rollback; the region has an outage and there is no runbook.
The move
GitHub Actions on every PR: typecheck, lint, unit, contract tests, migrate diff check, build, and Playwright E2E. A preview deploy per PR with an ephemeral Neon branch database. Migrations gated and applied on deploy with a rehearsed rollback. A staging environment mirroring production. Infrastructure-as-code for the non-Vercel pieces (indexer, workers). A public status page and a disaster-recovery runbook with explicit RPO/RTO targets.
13

Testing & QA

13

Coverage across contract, API, UI, E2E

Not built
Now
One Hardhat test. Zero API, component, or end-to-end tests. No CI to run them in.
Breaks when
Any refactor — there is no safety net, so every change is a gamble and regressions ship silently.
The move
Vitest for lib and API route handlers; React Testing Library for the wizard and mint panel; Playwright covering sign-up → catalogue → mint against a local Anvil chain. Expand the contract suite with Foundry fuzz and invariant tests plus gas snapshots. A coverage gate, a staging smoke suite, and a load test on the verification endpoint.

Roadmap

Three phases, in order. P0 is not optional and not parallelizable with growth work — it is the foundation the rest sits on.

P0 — Harden

~4–6 weeks · 2 engineers

Make the platform trustworthy and reproducible. Nothing here is user-visible; all of it is load-bearing.

  • Own database + committed Prisma migrations running in CI against a shadow DB
  • Server-authoritative mint: minimal webhook indexer, client can only set MINTING
  • Contract access control: MINTER_ROLE or EIP-712 voucher; owner → Gnosis Safe; rotate the deploy key
  • Least-privilege DB role + RLS on; secrets manager; CSP and security headers; error-message hygiene
  • Auth hardening: confirm email, leaked-password protection, MFA, rate limits
  • Sentry + structured logs; Playwright happy-path E2E; GitHub Actions pipeline
  • Terms of Service and Privacy Policy published

P1 — Scale

~8–12 weeks · 3–4 engineers + design

Make it a product galleries pay for and that survives real volume.

  • Full design system; wizard autosave and inline validation; theme toggle; error/empty states
  • Organizations: teams, roles, SSO; Stripe billing and entitlement enforcement
  • Storage permanence: dual-pin + Arweave; image pipeline; moderation queue
  • Full indexer (Ponder or subgraph): transfer sync, drift reconciliation, live verification
  • Contract audit; Base + Polygon mainnet deploy; per-chain registry; royalty splitters
  • OpenTelemetry tracing; SLO dashboards; on-call; load testing

P2 — Grow

ongoing

Expand surface area once the core is solid.

  • Public verification API + gallery integrations (OpenAPI, webhooks); bulk back-catalogue import
  • NFC provisioning flow with tamper-evidence; marketplace / listing hooks
  • Internationalization; a mobile capture app; gallery-facing analytics and reporting
  • SOC 2 Type II
